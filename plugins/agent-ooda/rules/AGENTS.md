# OODA & Multi-Agent Router Policy (`agent-ooda`)

## 1. `AGENT_OODA_DEPTH` / `ROUTER_DEPTH` Recursion Guard (Check First)
- Check whether `AGENT_OODA_DEPTH` or `ROUTER_DEPTH` in your process environment is `1` or greater.
- When `AGENT_OODA_DEPTH >= 1` (or `ROUTER_DEPTH >= 1`), you are running as a headless worker dispatched by `agent-ooda`. Execute the assigned task directly with native file and command tools (`read_file`, `edit_file`, `write_file`, `run_command`).
- **NEVER** invoke `agent-ooda` when depth is `>= 1` (enforced with `exit 2` by the binary).

## 2. Thin Orchestrator & Dynamic `agent-ooda` Execution (depth unset or `0`)
- Keep the top-level Antigravity session as a thin orchestrator (`<10%` of total token burn): own planning, architecture decisions, live agent selection, build/test gate verification, and user reporting while offloading bulk work to `agent-ooda` (`~/.local/bin/agent-ooda`, provided by the `agent-ooda` plugin).
- **Dynamic agent decisions (do not hardcode models/efforts):** Inspect `agent-ooda --status` (or `agent-ooda --discover` to refresh the cached CLI model catalog) and `agent-ooda --usage` before selecting lanes. Look at each CLI's real active model, available models/aliases, effort control mechanism (`--effort` / `--reasoning-effort` flag on `agy`/`mcode`/`muse`/`grok` vs `via-model` tier/alias on `devin` and `vibe`), and discovered `--skill` catalog. Override dynamically per task via `--lane` (single or comma-separated priority, e.g. `--lane mcode,devin-fast`), `--model`, `--effort`, `--skill`, `--profile`, or `--timeout`, or persist per-stage / lane preferences with `--set-stage`, `--reset-stages`, `--set-cycle`, `--local`, and `--until-reset`. When `--model`/`--effort` are omitted, single-pool CLIs use their own config defaults while `devin-*` resolves its configured family pool (`fusion`, `swe-2`, `swe-2-flash`).
- **Per-stage OODA routing matrix & selectors (`v2.2.0`):** `observe`, `orient`, `act`, and `verify` each default to `auto` (`Decide` remains with the user / top-level orchestrator) and resolve with precedence `CLI flag > --local > --profile > global > auto`. Pinned stages soft-failover on 429/quota (scrubbing primary-lane `--model`/`--effort` overrides when failing over to another lane), while `verify` always enforces an off-family reviewer. Configure via `agent-ooda --select` (`-s`, `b`/Backspace to go back, live `agy` theme colors), `/lane` inside chat, or 8 native `agy` `/agents` profiles (`ooda-auto`, `ooda-conserve`, `ooda-deep`, `ooda-devin`, `ooda-grok`, `ooda-mcode`, `ooda-muse`, `ooda-mistral`).
- **Codebase exploration & orient:** Run `agent-ooda --recon "<specific question>"` (prefers free `devin-fast` / `mcode` unless `--lane` specifies otherwise; read-only workspace snapshot-guarded, skips unrequested skills) before reading large sets of files directly, and `agent-ooda --orient "<question>"` (`OODA:ORIENT`, `deep` read-only analysis) for root-cause and architectural trade-off synthesis.
- **Coding, debugging & test sweeps:** Dispatch via `agent-ooda --task "<prompt>" --files ...` or parallel worktree manifests (`agent-ooda .worktrees/tasks.json` for 2+ disjoint modules). By default `auto` drains renewable `capped` 5h/7d/30d cycles (`agy-opus`, `muse`, `grok`, `mistral`) ahead of unlimited/high-cap lanes (`devin-pro`, `devin-fast`, `mcode`); paid `devin-fusion` credits require explicit `--lane devin-fusion`.
- **Multi-module work (2+ modules or non-trivial bugs):** Activate and follow the `agent-ooda` skill (`Observe -> Orient -> Decide -> Act`, zero edits before Phase 4, hard cap of 3 Act loops).
- **Independent code review:** Run `agent-ooda --review .` (supports `--lane`, `--model`, `--effort`, `--exclude-lane`; defaults to cross-model fallback starting with `mcode`, off the author family, never `devin-fusion` credits) on diffs rather than spending orchestrator tokens reviewing diffs inline.
- **Quota protection (enforced guardrail):** Worker lanes hard-reject (`exit 2`) any `gemini*` or `orchestrator*` model across `--model`, env vars, `--set-cycle`, manifest tasks, and dispatch. If `agy` defaults to a Gemini/Orchestrator model, `agent-ooda` auto-selects a non-Gemini Claude model discovered from `agy models` (never draining the Gemini orchestrator pool).
- **TUI step badges (`toolSummary`):** When invoking `agent-ooda` via `run_command`, include the OODA stage and chosen lane in `toolSummary` (e.g., `'OODA Observe [devin-fast]'`, `'OODA Act [agy-opus]'`, `'OODA Act parallel ×2'`, `'OODA Verify [mcode]'`).
